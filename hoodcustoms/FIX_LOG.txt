DIAGNOSTIC DETAILLE - POURQUOI LE SCRIPT NE MARCHAIT PLUS
--------------------------------------------------------------------------------
[PROBLEME N.1 - FATAL]  Deces du depot GitHub (cause N.1 du plantage)
  Le script telechargeait sa librairie UI depuis Internet :
    getgenv().Library     = loadstring(game:HttpGet(getgenv().repo .. getgenv().libraryFile))()
    getgenv().SaveManager = loadstring(game:HttpGet(getgenv().repo .. 'addons/SaveManager.lua'))()
    getgenv().ThemeManager= loadstring(game:HttpGet(getgenv().repo .. 'addons/ThemeManager.lua'))()
  avec repo = 'https://raw.githubusercontent.com/sonderdevyo/sonder/refs/heads/main/'
  Ce depot GitHub n'existe plus (supprime / 404). game:HttpGet() renvoie donc une
  erreur HTTP -> loadstring echoue -> le script meurt DES LE PREMIER CHARGEMENT.
  => Le script ne pouvait PLUS S'EXECUTER DU TOUT.

  BONNE NOUVELLE : le fichier "message (2).txt" que vous avez est EXACTEMENT
  cette librairie UI (celle qui etait telechargee depuis GitHub). Elle est donc
  maintenant EMBARQUEE directement dans le script corrige : plus besoin d'Internet.

[PROBLEME N.2]  getgenv().Workspace jamais defini (5 utilisations)
  Le script utilisait getgenv().Workspace (lignes ~1648, 1705, 1788, 1846, 1858)
  mais ne le definissait jamais. En Roblox Lua, getgenv() renvoie l'environnement
  global : getgenv().Workspace etait donc nil -> erreurs "attempt to index nil"
  quand on activait le Desync / le visualiseur.
  => CORRIGE : ajout de  getgenv().Workspace = workspace

[PROBLEME N.3]  getgenv().GuiService jamais defini (1 utilisation, auto-rejoin)
  => CORRIGE : ajout de  getgenv().GuiService = game:GetService("GuiService")

[PROBLEME N.4]  Toggles.DesyncToggle:SetText() n'existe pas dans la librairie
  Le script appelait Toggles.DesyncToggle:SetText(...) mais la methode SetText
  n'existait pas sur les toggles de la librairie -> erreur en activant le toggle.
  => CORRIGE : methode Toggle:SetText() ajoutee a la librairie embarquee.

[PROBLEME N.5]  Mauvaise casse des toggles (Lua est sensible a la casse)
  - Toggles.SpoofStrafe     (lu dans le loop de stomp) mais le toggle est enregistre
    en minuscules "spoofstrafe" -> nil.Value = crash silencieux du stomp.
    => CORRIGE : Toggles.spoofstrafe
  - Toggles.VisualizeStrafe (3 utilisations) mais enregistre en "visualizestrafe".
    => CORRIGE : Toggles.visualizestrafe

[PROBLEME N.6]  getgenv().stopStrafe() n'existe pas
  Le loop de stomp appelait getgenv().stopStrafe() qui n'a jamais ete defini
  dans getgenv() (c'est une fonction locale). => CORRIGE : stopStrafe()

[PROBLEME N.7]  Toggles/Options utilises mais JAMAIS crees dans le menu
  Le code utilisait ces reglages (avec des gardes nil, donc pas de crash, mais les
  fonctionnalites etaient INACCESSIBLES dans l'interface) :
    - Toggles.SpectateTarget      -> AJOUTE (onglet HvH > groupe Strafe)
    - Toggles.LookAtTarget        -> AJOUTE (onglet HvH > groupe Force Hit)
    - Toggles.AutoHealEnabled     -> AJOUTE (onglet Misc > groupe Auto)
    - Options.AutoHealThreshold   -> AJOUTE (idem)
    - Toggles.AutoVoidOnHit       -> AJOUTE (onglet HvH > groupe Desync)
    - Options.AutoVoidOnHitDuration -> AJOUTE (idem)
    - Toggles.CSyncEnabled        -> AJOUTE (idem)
    - Options.CSyncType           -> AJOUTE (idem, valeurs Void/None)

[PROBLEME N.8]  SaveManager / ThemeManager
  Ces 2 modules etaient aussi telecharges depuis le depot mort. Ils sont remplaces
  par des implementations locales (stubs) compatibles avec les appels du script :
    SetLibrary / SetFolder / BuildConfigSection / IgnoreThemeSettings /
    SetIgnoreIndexes / LoadAutoloadConfig / Save  (SaveManager)
    SetLibrary / SetFolder / ApplyToTab            (ThemeManager - ajoute aussi
    un selecteur de couleur d'accent "AccentColor" dans l'onglet Settings, ce qui
    fait fonctionner le code existant qui lisait Options.AccentColor).
